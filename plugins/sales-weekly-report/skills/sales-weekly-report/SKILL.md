# 주간 판매 리포트 생성

`판매관리.xlsx` 한 파일에서 주간 리포트 엑셀을 만드는 고정 워크플로우다.
계산과 서식은 전부 `scripts/build_report.py`가 처리한다. 직접 openpyxl 코드를
새로 짜지 말 것 — 스크립트가 이미 검증된 수식·서식·정렬 규칙을 담고 있고,
매주 같은 결과가 나와야 비교가 의미 있다.

## 전제하는 파일 구조

이 스킬은 아래 구조를 전제한다. 다르면 스크립트가 `structure_error`로 멈춘다.

- 시트 `판매`: `날짜 | 품목명 | 카테고리 | 단가 | 판매수량 | 매출액 | 판매채널` (누적 데이터)
- 시트 `재고`: `품목명 | 카테고리 | 현재재고 | 안전재고 | 재고상태 | 최근입고일 | 입고수량 | 단가 | 재고금액 | 보관위치` (현재 스냅샷)

## 실행 절차

**1. 폴더 확보.** 판매관리.xlsx가 있는 폴더에 접근할 수 없으면 먼저 접근을 요청한다.
보통 `~/Downloads/판매데이터관리`에 있다. Cowork에서는 `request_cowork_directory`.

**2. 데이터 범위부터 확인한다.** 스크립트를 돌리기 전에 실제 날짜 분포를 눈으로 본다.
기준일(`--asof`)이 데이터 최신일과 어긋나면 빈 리포트가 나온다.

```bash
python3 -c "
import glob, openpyxl, collections
p=[x for x in glob.glob('<폴더>/*.xlsx') if '~\$' not in x and '판매관리' in x][0]
ws=openpyxl.load_workbook(p, data_only=True)['판매']
ds=sorted({str(r[0])[:10] for r in ws.iter_rows(min_row=2, values_only=True)})
print(ds[0], '~', ds[-1], '/ 총', len(ds), '일')
"
```

최신 데이터가 오늘로부터 한 주 이상 과거면 **추측하지 말고 사용자에게 어느 주를
대상으로 할지 물어본다.** "지난주 걸 달라는 건지, 데이터가 밀린 건지"는
데이터만 봐서는 알 수 없다.

**3. 리포트 생성.**

```bash
python3 <skill>/scripts/build_report.py --folder "<폴더>" [--asof YYYY-MM-DD] [--lead-time 7]
```

- `--asof` 생략 시 오늘 기준. 특정 주를 뽑으려면 그 주에 속한 아무 날짜나 주면 된다.
- `--lead-time`은 권장발주량 계산에 쓰는 조달 소요일. 기본 7일.
- `--out-dir` 생략 시 원본과 같은 폴더에 저장한다.

스크립트는 JSON으로 핵심 수치와 재계산 결과를 돌려준다. `recalc.status`가
`success`가 아니면 사용자에게 그대로 보고한다. 수식이 계산되지 않은 파일은
엑셀에서 빈 셀로 보이므로 그냥 넘기면 안 된다.

**4. 결과 보고.** 파일을 `present_files`로 제시하고, JSON에 담겨 온 수치로
짧게 요약한다: 총 매출·건수·전주 대비 증감, 채널 순위, 재고 부족 품목 수와
가장 급한 품목. 리포트에 이미 다 들어 있으니 표를 다시 옮겨 적지 말 것.

## 굳어진 규칙 (스크립트에 반영되어 있음)

이 규칙들은 사용자와 합의된 것이다. 바꿔달라는 요청이 없으면 유지한다.

- **주 = 월요일~일요일.** 원본 데이터가 월요일에 시작하고 일요일 기록이 없다.
- **영업일은 거래 기록이 있는 날만 센다.** 휴무일을 분모에 넣으면 일평균이 왜곡된다.
- **파일명 = `{월}월 {N}주차.xlsx`**, N은 그 주 월요일이 그 달의 몇 번째 월요일인지로 정한다. (8/24 월 → `8월 4주차.xlsx`)
- **원본 무수정.** 항상 새 파일로만 저장한다.
- **모든 수치는 수식으로.** 파이썬으로 계산한 값을 하드코딩하지 않는다. 원본 데이터 시트를 같이 넣어 두었으므로 사용자가 셀을 고치면 리포트가 따라 움직인다.
- **재고 긴급도 = 소진 예상일(현재재고 ÷ 일평균 판매량) 오름차순.** 부족 수량 절대값보다 "며칠 뒤 바닥나는가"가 발주 순서를 정한다. 이번 주 판매가 없는 품목은 후순위.
- **권장발주량 = 부족수량 + (일평균판매 × 리드타임).**
- **가정은 반드시 시트에 적는다.** 주 기준, 영업일 수, 리드타임은 리포트 하단과 각 표 아래 주석에 명시된다.

## 출력물 구조

`{월}월 {N}주차.xlsx` — 시트 3개:

- `주간리포트` — 위에서 아래로 1.요약 → 2.판매 분석(2-1 품목별 / 2-2 채널별) → 3.재고 현황 → 4.액션 아이템
- `데이터_이번주판매` — 해당 주 원본 행 (모든 수식의 참조 대상)
- `데이터_재고` — 재고 스냅샷

액션 아이템은 P1(긴급) / P2(금주) / P3(차주)로 나뉘고, 각 항목마다 근거가
어느 분석에서 나왔는지 함께 적힌다. 담당·기한 칸은 사용자가 채우도록 비워 둔다.

## 자주 걸리는 함정

- **macOS 한글 파일명은 NFD 정규화**라 `'판매관리' in 이름` 같은 비교가 조용히 실패한다. 스크립트는 `unicodedata.normalize("NFC", ...)`로 처리하고 있지만, 직접 경로를 다룰 때도 리터럴 경로 대신 `glob`으로 찾을 것.
- **LibreOffice 재계산을 마운트된 사용자 폴더에서 직접 돌리면 타임아웃**이 난다. 스크립트는 로컬 임시 폴더로 복사해 계산한 뒤 되돌려 놓는다.
- **`~$판매관리.xlsx` 같은 잠금 파일**은 엑셀이 열려 있다는 뜻이다. 읽기는 되지만 후보 목록에서 걸러야 한다.
- **구조가 다르면 `structure_error`로 멈춘다.** 이때 컬럼을 임의로 추론해 진행하지 말고, 스크립트가 출력한 "기대 vs 실제"를 그대로 사용자에게 보여주고 어떻게 맞출지 물어본다.
